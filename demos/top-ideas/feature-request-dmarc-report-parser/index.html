Problem statement

Gap: Self-hosted mail admins (Mailcow and peers) get raw DMARC aggregate reports and need readable pass/fail/fail-source dashboards without buying enterprise email security suites.
Why host won’t: Mailcow feature request for a DMARC report parser stays open; operators still forward XML to third parties or ignore reports.

Solution (MVP wedge)

Solo SaaS: drop a mailbox/API for DMARC rua reports → parse → weekly digest + simple domain dashboard. Start Mailcow-friendly docs, then any self-hosted MTA. Concierge: manually parse a customer's last 30 days of reports in week 1.
Competition / workarounds: dmarcian, Valimail, Postmark DMARC, DIY scripts. Wedge is cheap, self-host-mailer-friendly onboarding (not enterprise SOC).
Kill criteria: Mailcow ships a good enough built-in parser, or <3 paying admins after concierge.

Flow(s)

  • 1. Ingest: receive DMARC rua aggregate reports (mailbox/API import).
  • 2. Parse: extract per-domain pass/fail and source metadata into normalized tables.
  • 3. Dashboard: show trends and “top offenders” with plain-English explanations.
  • 4. Export: provide a weekly summary for admins (and optionally per-domain drill-down).

Investor-friendly pitch snippet

Wedge: Self-hosted mail admins (Mailcow and peers) get raw DMARC aggregate reports and need readable pass/fail/fail-source dashboards without buying enterprise email security suites. Moat: We ship the workflow end-to-end: input -> run -> explain -> iterate, with fast onboarding. First customer demo: Start with manual concierge for 1 week, then productize the repeatable core loop.
